# 阶段二：按问题模块成文

本文件仅在阶段二读取，管全书骨架、模块化写作、抽象落地、来源取证与断点补足。

## 全书骨架

```md
# <主题>                          # 全书唯一 H1

## 全书地图
## 学科定位
## <问题模块 A>
## <问题模块 B>
## ...
## 总复习
## 术语表
## 想深入的话去读什么
## 本书故意没讲什么
```

固定板块交付标准：

| 节 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 全书地图 | 一张 Mermaid「核心问题与解决主线图」（必选）+ 跨模块复用复杂或有路线分歧时加一张「关键联系与竞争图」+ 一段阅读路线 | 每个问题模块都落在主线图节点上；基础枢纽的跨模块贯穿已标出 |
| 学科定位 | 核心研究对象的正面界定 + 核心问题 + 学科定位与边界 | 研究对象界定清晰，后续模块直接回指；边界写明“到这里为止，再往前是别的学科，再往后是应用” |
| 总复习 | 一页式全书概括 | 每个问题模块一行概括并准确指向对应模块 |
| 术语表 | 术语 / 英文原词 / 一句话定义 | 与 `syllabus.md` 的 `terms` 逐条一致 |
| 想深入的话去读什么 | 未展开的细节去哪里拿（对应原素材章节或实操路径）+ 下一步更窄的主题 | 每条能指回实际读过的素材章节或具体的进阶主题 |
| 本书故意没讲什么 | 有意省略的专题、深度边界、课程明确排除项与 `[未解决]` 缺口 | 覆盖被剔除的主题、考核排除项及缺口清单中的 `[未解决]` 条目 |

固定板块外不再追加尾节；历史演变融入各问题模块，不单独设历史章。

## 模块与单要点写法

### 模块三段结构

- **开场**：用一个具体的现实场景或困惑切入，点明它如何承接前面已交付的板块或前置知识。非竞争关系的板块按实际推进关系自然衔接（如延伸约束、换了场景、各管一段）；仅在确实存在前序方案失灵且有具体事例时才写“A 不够所以有了 B”。
- **主体**：逐个展开本模块的重点与常规要点，按篇幅与阅读节奏自然起 H3 小标题；「带过」要点用一两句附在最相关的要点后，不单独成节。
- **收尾**：指明本模块方案在何处达到上限或引出新困惑，自然过渡到下一问题模块；若有「重点」要点，附 1~2 句不紧挨答案的简短反思引子（提示先闭卷自答再回上文核对，避免“看懂即学会”的流畅度错觉），并说明可随时进入测验分支练手。

### 单要点三件事

每个「重点 / 常规」要点在同一处一次讲全三件事：
1. **为什么需要它**：挂在解决主线的哪一环，没有它什么问题解决不了；
2. **它是什么、怎么运作**：定义、核心机制与适用条件一次交付完整；
3. **它的局限与边界**：什么条件下会失灵或不够用，借此引出后续要点或方案。

### 基础枢纽与竞争方案

- **基础枢纽**：在首次出现的模块一次讲透完整机制；后续模块每次用到时直呼其名显式回指、累积理解，不重复铺陈定义。
- **竞争方案**：同一问题存在互相竞争的理论、流派或解法时，从顺接叙事中显式标出对比——给出一个具体现象或场景，说明各方如何处理、各自前提条件以及取舍依据。

## 解释、落地与表达

- **先界定再使用**：任何支撑后续论证的概念，均须在首次使用前由前置知识或更早位置界定清楚；公式先讲直觉含义再写符号，数学推导与图示深度遵循阶段一确定的考核口径与 `depth` 设定。
- **先主干再叠例外**：讲解复杂机制或基础枢纽时，先用一个干净的标准场景跑通主干逻辑让读者拿到确定感，再叠加前提限制、特例与反例，避免一出场就把所有例外压进工作记忆。
- **抽象概念落地与反向检验**：抽象概念首次出现时落到具体（生活场景对应概念要素、带具体数字或量级的演示、或一句可观察现象）。写完例子后做一次**反向检验**：改掉例子里的关键条件，概念的结论是否跟着改变？会变说明例子承载了机制；不会变就换成数字演示或可观察现象。
- **取舍与密度**：保留支撑解决主线的核心机制与素材独有洞见，剔除同质重复的论证例子（`depth: outline` 时每要点保留一个最短路径例子；`full` 时重点要点保留完整推演与关键例证）。概括性总结与支撑材料只能留一个时，留材料。
- **图表与版式**：
  - 当结构不再是单向线性推进（如全书总览、多路流程、并列对比、后文修正前文结论）时，使用内联 Mermaid（样式规范参考 `markdown-mermaid-writing` skill）。坚持一图一任务，先点明图要回答的问题再放图，图紧跟首次引用的段落。
  - 散文承载论证，确凿并列项用列表，同结构字段重复三次以上用表格。
  - 一段围绕一个核心断言；关键断言适度加粗，原话本身是重点（定义或原典表述）时才用引用块。
  - 交叉引用直接写出准确的板块名、核心概念名或自然位置词（如“前面讲过”），不自造章节编号或临时别名。

## 来源纪律与断点检索

- 每个模块的事实依据回到原始素材或已记录的外部权威来源，不从自己前面已写的正文反推事实。素材内部不同材料口径矛盾时，并列说明差异并写明采纳口径与理由。正文不挂引注，来源定位记入 `_notes/structure.md`。
- **断点搜索纪律**：外部搜索只用来修复阻断后续主线推进的解释**断点**，不将课程扩写成开放式百科。遇到断点按三步处理：
  1. 回到相关素材确认无法通过调整上下文顺序解决；
  2. 确认缺失环节确实阻断后续关键概念的理解或承接（仅缺背景故事时不搜索）；
  3. 把缺口改写成一个具体问题，调用 `$web-access` 定向检索并打开权威原文（课程指定参考书、官方文档、原始论文）核实后采用，接回主线即停。
- 外部补足的来源与修复断点记入 `_notes/structure.md`；若外部资料要求增删问题模块或纠正素材核心事实，按 `[结构性介入]` 记入缺口清单并走结构冲突流程；仍无法补足的记为 `[未解决]`，并在书末「本书故意没讲什么」交代。

## 板块级硬检（6 条）

每写完一个问题模块，逐条核对通过后才可置为 `done`：
1. 标题与 `sections[].title` 逐字一致，以真实问题场景开场，收尾自然引向下一模块；
2. 每个重点/常规要点一次讲全三件事（为什么需要、是什么与怎么运作、局限边界），「带过」要点未单独成节；
3. 每个支撑论证的概念均已先行界定，抽象概念已通过反向检验落到具体；
4. 基础枢纽已显式回指，竞争方案已讲清前提差异与取舍；
5. 本模块事实依据均回溯至原始素材或已记录的权威外部来源，外部补足仅限修复断点；
6. 图表一图一任务且紧跟首引段落，无自造编号或临时别名，术语符合 `terms`。
